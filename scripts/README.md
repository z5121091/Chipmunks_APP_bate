# 掌上仓库 ERP版同步助手说明

`label_sync_server.py` 是掌上仓库 APP 的电脑端同步助手。手机端把 Excel 数据发送到本机服务后，同步助手会把文件保存到电脑目录，便于后续打印、归档或导入其他系统。首页的“标签补打”使用独立的内存打印接口，不保存 Excel 或补打业务记录。

## 双击构建与新电脑环境

根目录双击 `掌上仓库构建工具.exe`，选择“同步助手”并点击“开始构建”。构建前会检测可用的 Python 3.10–3.12 64 位和 `sync-build-requirements.txt` 中的已验证打包依赖；兼容时直接复用。缺少 Python 时从 Python 官网准备 3.12.10，缺少依赖时使用独立虚拟环境，不往原有 Python 中安装或升级依赖。之后继续原有 PyInstaller 构建，输出仍为 `scripts/dist/`。

配对设置窗口使用 Python 自带的 Tk 桌面组件。构建前会实际检查 Tk 和 Tcl/Tk 数据文件；新装项目 Python 时包含这些组件，旧项目运行时缺失时可补齐。若使用外部安装的 Python 且缺少 Tk，会提示在该 Python 安装器的 Modify 中启用 “Tcl/Tk and IDLE”，不自动修改外部安装。打包后的 EXE 自带这些组件，运行电脑无需另外安装 Python。

构建工具缓存位于 `%LOCALAPPDATA%\ChipmunksBuildTools`，仅支持 Windows Intel/AMD 64 位。重复运行会复用已经验证的工具和下载；下载安装失败、版本验证失败或另一窗口正在准备时，会停止并提示原因。

仅检查、不下载或构建：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -CheckOnly`。只准备同步助手环境、不生成 EXE：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -PrepareOnly`。

根目录 `准备构建环境.bat` 可以一次准备 APK 和同步助手两种环境。APK 的签名、NAS 配置及 SDK 许可说明见 [本地构建文档](../docs/local-android-build.md)。这些入口用于从完整源码构建；已打包的 EXE 自带运行环境。脚本不自动变更应用或同步助手版本号。

当前版本为 `V1.0`：同步助手会识别实际局域网 IPv4、避开代理与虚拟网卡，并在网络地址变化后自动刷新托盘中的服务地址。版本可在托盘菜单和 `/health` 接口核对。

## 桌面业务通知

入库、出库、盘点单、订单标签同步，以及拆包打印和标签补打复用托盘已有的 Windows 通知：

- 入库、出库：Excel 文件原子保存完成后提示记录条数和文件名；保存失败提示文件占用/权限、磁盘空间或数据格式等摘要。
- 盘点单：保存完成后显示“盘点单同步完成”，包含所有工作表的数据行总数与文件名；保存失败时显示失败摘要。
- 设置中的“同步订单标签”：只在标签 Excel 保存后显示“订单标签同步完成”，不启动打印。旧版通过盘点接口导出“拆包标签”的兼容路径也归入订单标签通知。
- 拆包：新任务提交 Windows 打印队列后提示实际标签张数（包括拆包时间标签），使用“已提交打印，请核对出纸”的表述。部分供应商没有模板时，同一条通知同时说明跳过条数；全部没有模板时提示“已保存，本次未打印”。
- 标签补打：新任务提交后显示“补打标签已提交打印”，每次两张；同一个已提交任务的重复请求不重复提醒。失败与出纸结果不确定分别通知。
- 出纸结果不确定时提示先核对打印机，再决定是否重试；同一个已提交任务的重复请求不重复弹成功通知。
- 同类成功结果在 1.5 秒窗口内合并；相同类型、原因的连续失败或结果不确定通知在 30 秒内最多提示一次。确认恢复后再次失败会重新提醒；新失败会取消同类尚未弹出的旧成功摘要，避免顺序误导。

通知由独立线程发送，HTTP 处理只将摘要放入有界内存队列。桌面通知不可用或发送失败不会改变文件保存/打印结果，不增加 ERP 调用或 PDA 轮询。退出时立即丢弃待发通知，不等待已进入的系统通知调用（已提交给系统的通知无法撤回）；尚未发送的通知不会保存到磁盘或在下次启动补发。

标签补打使用专用的不记录日志发送回调，只传通用结果和张数，不携带型号、二维码、追溯码、任务标识或原始异常；专用回调不可用时忽略通知，不回退到会写日志的普通通知。补打回执和通知摘要只在内存中保留，仍不写数据库、Excel、JSON、补打历史或通知日志。新功能在电脑端生效，发布时只需构建并运行更新后的同步助手 EXE；不会自动构建或升级版本号。

## 运行方式

### 直接运行

```bash
pip install cherrypy openpyxl pystray Pillow qrcode pywin32 pyinstaller
python label_sync_server.py
```

### 打包成 EXE

打开根目录 `掌上仓库构建工具.exe`，选择“同步助手”并点击“开始构建”。

成功时工具会提供本次带时间戳的 EXE，并保存 SHA256 与校验记录。`scripts/dist/掌上仓库ERP版同步助手.exe` 仅在成功后更新；若旧文件被占用，保留旧件并提示使用新生成的时间戳文件。工具不会自动启动或结束同步助手。打包后手动打开本次 EXE 即可运行。运行后程序会以“掌上仓库 ERP版同步助手”常驻系统托盘，便于和旧版同步服务区分。

## 标签补打

首页“标签补打”解析扫描到的物料码，再按型号对应的物料绑定查找供应商模板。版本号只作为标签内容，不参与供应商匹配。没有解析规则、没有对应模板或字段无法完整打印时，会明确提示原因；补打不会退回 Excel 上传接口。

`POST /label-reprint` 只打印原标签两张，不生成另一种拆包标签或拆包时间标签。原二维码逐字符保留，包括原来的分隔符和空字段。补打不会写入数据库、标签 Excel、JSON、打印历史文件或含标签内容的日志；重试去重回执只保留在同步助手进程内，退出后清空。Windows 打印队列接受任务只表示已提交；若发送途中发生异常，需先核对实际出纸情况，再确认重试。

补打二维码由 `qrcode` 在内存中生成确定的 Model 2 矩阵，使用 L 级纠错、S7 掩码和自动编码。矩阵直接绘制进标签黑白位图，保留四周各四模块的白边，不再由打印机自行决定补打二维码的版本，也不对成品二维码图片进行拉伸。

原始二维码中的回车（CR）、换行（LF）及 CRLF 会作为原始数据完整编码，不删除、不替换、不统一行尾，也不拼入 TSPL 指令文字。型号、批次、箱号等纸面字段继续拒绝控制字符；原码中的制表、空字符及其他不支持字符仍会明确报错。

补打按每个模板原本的二维码整体大小选择整数点单元：极海、领芯、博雅和沁恒的主体目标约 198 点（24.8 毫米），盈力约 132 点（16.5 毫米）。单元取 3–10 点中能够完整放入模板区域、且主体大小最接近目标的一档。原码长度和编码版本不同，整体尺寸会按整数单元略有变化；无法完整容纳时明确报错，不截断二维码或静默裁掉白边。沁恒二维码与下方独立追溯码保持同一中心线。

极海、领芯补打的追溯码文字和一维码按真实宽度使用同行空白，支持尾部序号从一位增加到两位、三位等正常长度变化。文字保持 Arial 8 磅，一维码保持预设 2 点单元；条码与左侧封装条码及右侧合规文字留有至少 10 模块的静区。真正超出剩余空间的字段仍明确报错，不截断或压窄内容。此布局适配仅用于补打，旧拆包模板保持原有输出。

上述矩阵绘制仅用于标签补打。下方拆包自动打印仍使用原模板的原生二维码指令和已有尺寸选择策略。`build.ps1` 安装并收集 `qrcode` 打包依赖；修改源码不会自动重建 EXE，发布仍需用户明确要求。

## 拆包标签自动打印

扫码出库确认拆包后，APP 会先把原有 `标签打印.xlsx` 保存到同步目录，再向同步助手提交一次明确的原生打印任务。每次正常拆包共打印五张：发货标签两份、剩余标签两份、拆包时间标签一份，五张使用同一个打印任务标识去重。

拆包时间标签尺寸为 `100x50mm`，与极海标签一致；使用 Windows 微软雅黑绘制中文，保留原有供应商标签的 Arial 字体。内容为物料型号、存货编码、固定文字 `MSL-3`、最后拆包时间和固定状态文字 `已入干燥柜 / 敞口存放`。状态仅为印刷文字，不表示软件确认物料已经入柜。时间读取 Excel 的“拆包时间”，不会用重新同步或打印时的当前时间替代；旧数据缺少有效时间时显示 `-`。该标签不需要追溯码。

此新增标签由电脑端同步助手生成；现有 APP 标签 Excel 已包含所需字段，不需要新增数据库字段或 ERP 接口。其他供应商仍沿用下方的不自动打印策略。已有打印历史的任务不会因升级而自动补打一张，以免重复出纸。

默认打印队列名称为 `TSC TTP-244 Pro`。如果公司电脑中的实际打印队列名称不同，请在启动同步助手前设置环境变量：

```bat
set PALM_WAREHOUSE_PRINTER_NAME=你的实际打印机名称
```

设置后重新启动同步助手。若自动打印失败，PDA 提示和日志保留详细原因；桌面通知显示失败摘要。打印机名称不符时，可从详细提示中核对当前 Windows 可用的打印队列名称。

- PDA 成功时不显示额外的打印任务提示；打印失败时才会提示。
- 设置中的“同步订单标签”仍然只导出 Excel，不会触发打印。
- 每次拆包使用唯一任务标识；网络超时或重复提交不会重复出纸。
- ERP 版自动打印使用 `native_tsc_supplier_v2` 协议；旧同步助手不支持该协议，因此不会误用旧版“所有拆包都打印”的逻辑。
- 标签 Excel 会携带物料绑定中的“供应商”字段，并按供应商全称选择模板：
  - `珠海极海半导体有限公司`：使用现有“极海”模板，保留 Geehy Logo。
  - `珠海领芯科技有限公司`：使用“珠海领芯”模板，版式与极海一致但不显示 Logo。
  - `珠海博雅科技股份有限公司`：使用“珠海博雅”模板，显示 BYT Logo、BOYA MICROELECTRONICS 品牌栏、六行物料信息、合规标识和二维码。
  - `南京沁恒微电子股份有限公司`：使用“南京沁恒”模板，左侧八行物料信息，右侧 WCH 沁恒 Logo、二维码及二维码下方独立追溯码。
  - 其他供应商或未填写供应商：仍保存 `标签打印.xlsx`，但不自动打印，后续可手动打印。
- 二维码分隔符由供应商模板决定。极海、领芯和珠海博雅使用 `/`，盈力使用 `;`，南京沁恒使用英文逗号 `,`。极海和领芯按固定八字段写入：型号、批次、封装、版本或 APM 料号、数量、生产周次、追溯码、箱号。珠海博雅按固定六字段写入：型号、封装、数量、批次、生产日期、箱号。
- 标签正文统一使用 Arial 8 磅；`COO:CN`、`RoHS`、`MSL3` 使用 Arial 粗体 8 磅。博雅顶部 `BOYA MICROELECTRONICS` 使用 Arial 14 磅并在纸张宽度内居中。
- Geehy 与珠海博雅品牌区域分别使用 `assets/geehy-logo.png` 和 `assets/boya-logo.png`；构建 EXE 时会自动打包整个 `assets` 目录。
- 博雅标签的 `PART NO.`、`PACKAGE`、`QUANTITY`、`LOT ID`、`DATE CODE`、`Track ID` 分别关联 Excel 中的型号、封装、标签数量、批次、生产日期、箱号；不使用追溯码。`MSL3` 为固定文字。
- 二维码使用自动版本、自动编码、L 级纠错与 `Model 2 / S7`。极海、领芯和博雅的二维码单元均约 `0.75 mm`，且与相邻内容保留独立白边。
- 按 BarTender 参数换算：型号使用 1 点宽（约 `0.13 mm`）；`BOX ID`、`LOT NO`、`PKG`、`P/N`、`QTY`、`DATE`、`T/C` 使用 2 点宽（约 `0.25 mm`）；全部高度为 32 点（`4.0 mm`）。
- 极海和领芯一维码高度为 4.0 毫米并关闭条码下方的可读字符；博雅原版式不打印一维码。
- 同步助手会在电脑端用 Windows Arial 生成小型黑白文字层，再配合打印机原生条码输出；不会向打印机安装、删除或下载字体，避免打印机进入错误状态。
- 同步助手不会切换热敏或热转印模式；TSC TTP-244 Pro 会继续沿用打印机当前的碳带热转印设置。
- 12 位纯数字的 APM 料号会打印在 `P/N`，不会再误显示为 `VER`；真正的短版本号（例如 `B1`）仍显示在 `VER`。

## 标签模板目录规范

打印服务与标签版式已经分离，模板统一位于 `label_templates`：

```text
label_templates/
├── common.py      # Excel 字段、Arial 字体、图片和位图公共逻辑
├── apm.py         # 极海、珠海领芯共用版式
├── boya.py        # 珠海博雅版式
├── union.py       # 盈力半导体版式
├── wch.py         # 南京沁恒版式
├── unpack_time.py # 每次拆包额外一张的中文时间标签
└── registry.py    # 供应商全称与标签模板的唯一映射
assets/            # 所有模板使用的 Logo 和合规图片
```

所有模板从 Excel 统一读取 `型号`、`标签数量`、`批次`、`生产日期`、`封装`、`追溯码`、`存货编码`、`箱号`、`版本号`、`标签类型`、`供应商`、`拆包时间`。新增定型供应商标签时，只需增加一个模板文件和所需图片，再在 `registry.py` 中登记供应商全称；不需要修改同步接口、去重历史或打印服务流程。

盈力半导体模板（供应商全称 `盈力半导体(上海)有限公司`）使用 100×50 mm 纸张。纸面 `DATE CODE` 取 Excel 的`箱号`，`MARK` 取`版本号`，`TRACE NO.` 取`追溯码`，`DATE` 取`生产日期`；二维码按`型号;标签数量;追溯码;批次;箱号;版本号;生产日期`生成。QA PASS 章不打印。

盈力模板的 ESD 和防潮小雨伞图标分别来自用户提供的 `1.png` 和 `2.png`，打印资源统一保存在 `assets/esd-warning.png`、`assets/keep-dry.png`。

南京沁恒模板沿用 100×50 mm 纸张。左侧依次显示 `Part No:`（型号）、`item No:`（版本号）、`Code NO:`（固定 `---`）、`Package:`（封装）、`LOT NO:`（批次）、`QTY:`（标签数量）、`DATE:`（原物料生产日期）、`Origin:`（固定 `China`）。二维码按 `型号,版本号,---,封装,批次,标签数量,生产日期,China,追溯码` 写入九个字段，共八个英文逗号，追溯码后不追加分隔符。二维码下方另打印本条标签的追溯码，使用原生二维码 `J2` 顶部居中定位，与追溯码共用中心线。不会把箱号、存货编码或拆包时间代入二维码。型号、标签数量与追溯码必填；其他字段缺失时保留二维码空字段，纸面用 `-` 提示，不伪造追溯码。

沁恒 Logo 使用用户提供的原图，保存为 `assets/wch-logo.png`，在 20×5 mm 范围内保持纵横比并居中显示；现有热转印打印输出为黑白。文字固定 Arial 8 磅（203 dpi 下为 23 像素），不自动缩小字号；超出显示范围时明确报错。二维码使用 Model 2、自动版本与编码、L 级纠错，沿用现有原生打印的 S7 掩码，默认 6 点单元（约 0.75 mm），较长内容可减小单元并保留四单元白边；仍无法放入、或字段包含逗号、指令引号及不可打印字符时，明确报错而不截断数据。该模板复用现有拆包追溯码、标签份数、额外拆包时间标签及任务去重流程。发布 EXE 需用户明确要求后另行构建。

## 服务地址

默认端口：`8080`

健康检查地址：

```text
http://电脑IP:8080/health
```

手机端在“设置 -> 电脑同步”里填写电脑 IP 和端口后，可以测试连接。

### 可选的配对保护

同步助手默认沿用兼容模式：没有配置密钥时，旧 PDA 可以照常连接。程序不会自动生成或启用密钥，也不会修改现有用户配置。

在电脑托盘菜单点击“配对设置…”会打开设置窗口：

1. 勾选“启用配对保护”，输入自行设置的密钥，再点击“确定”。密钥为 1～128 个英文字母、数字或英文符号，不含空格和中文；默认以圆点隐藏，可勾选“显示密钥”核对。
2. 在 APP 的电脑同步设置中填写相同密钥，点击“测试连接”。APP 中“选填”的含义是：电脑未开启配对时可以留空；开启后必须一致。
3. 关闭保护时取消勾选开关，密钥输入框会禁用，无需输入密钥。点击“确定”后关闭保护并清空电脑保存的密钥；APP 留空或保留原有合法密钥都可以连接。以后重新开启时需重新输入密钥。
4. 点击“取消”、窗口关闭按钮或按 Esc，均不保存；首次仅打开窗口也不会创建配置文件。连续点击菜单会回到同一个设置窗口。

“确定”保存后立即生效，无需重启助手；托盘状态同时刷新。只在电脑改开关时，APP 状态提示可能随接下来 10～20 秒的心跳检查更新；在 APP 点“测试连接”可立即重新检查。已开始处理的请求继续完成，后续业务请求按新设置验证。

设置仍保存在同步数据目录的 `sync-helper-config.json`，兼容原有 `pairingKey` 配置并保留其他字段。保存采用同目录临时文件和原子替换；保存失败会保留窗口并说明原因，不覆盖原设置。配置损坏时会显示异常并禁止保存，避免误关闭已有保护。

Windows 下此配置文件默认设置为“隐藏”：启动助手时会为已有文件补上隐藏属性，每次成功保存后也会保持隐藏；没有配置文件时不会因此新建文件。资源管理器开启“显示隐藏的项目”后可查看。隐藏只改变文件的显示方式，不改变保存位置、密钥内容或配对验证；系统不允许修改属性时，配对读写仍按原逻辑工作。

高级部署仍可在启动助手前设置 `PALM_WAREHOUSE_SYNC_PAIRING_KEY`。该环境变量优先于文件配置，显式空值也会覆盖文件；这种情况下窗口会说明由启动环境控制，并禁用修改，避免保存后不生效。如需改用窗口管理，先移除启动环境变量再重启助手。`PALM_WAREHOUSE_SYNC_DIR` 可指定同步数据目录。不要把实际密钥提交到源码、截图或日志。

启用后，所有保存、拆包打印和标签补打的 `POST` 请求都必须携带 `X-Sync-Pairing-Key`。密钥在读取请求正文、保存文件和提交打印前校验，错误时返回 HTTP 401、`SYNC_PAIRING_REQUIRED`；配置损坏时返回 HTTP 503、`SYNC_PAIRING_CONFIG_ERROR`，不会降级成无保护模式。两者均带 `resultUnknown: false`、`retryAllowed: true`，表示本次没有保存或提交打印。

`GET /health` 保持可发现，返回 `pairingRequired`、`pairingAuthenticated` 和固定头名称 `pairingHeader`，不返回密钥；APP 据此区分在线但未配对与连接成功。`OPTIONS` 允许新的请求头，沿用不带 Cookie 的跨域访问方式。配对限制访问，不改变现有局域网 HTTP 传输方式。

同步助手只显示供同一局域网 PDA 访问的私有 IPv4 地址，不使用公网出口 IP。它会优先选择带默认网关的 Wi-Fi 或以太网网卡，并排除常见 VPN、代理、Docker 和虚拟网卡；网络切换或 DHCP 地址变化后，托盘菜单会在 15 秒内自动刷新，服务本身不需要重启。

APP 会保存已填写的电脑地址，因此电脑局域网地址真正发生变化时，仍需把托盘中显示的新地址在 APP 中更新一次。长期使用建议在路由器为电脑设置 DHCP 地址保留，这样地址不会随网络重连改变。若本机网络环境特殊、自动选择错误，可在启动同步助手前设置 `PALM_WAREHOUSE_SYNC_IP` 为指定的局域网 IPv4 地址。

## 数据保存目录

默认保存目录：

```text
D:\数据同步
```

同步助手会自动创建目录。手机端同步成功后，会返回实际保存的文件名。

### 拆包打印长期去重账本

拆包打印使用同步目录下的 `native-label-print-history.sqlite3` 长期保存任务回执，不再因超过 500 条而删除旧任务。日常提交按任务 ID 查询索引，仅存任务标识、内容指纹、提交状态、打印队列回执及数量等简要信息，不存标签原始二维码或整份 Excel。普通“标签补打”继续仅在内存中去重，不写入这个账本。

首次使用时，助手会在数据库事务中导入旧 `native-label-print-history.json`，保留旧文件；无状态字段的旧回执按已提交处理。后续以 SQLite 为准，不会重新导入旧文件来覆盖较新的未知或已提交状态。

提交 Windows 打印队列前先提交 `submitting` 状态，成功后改为 `submitted`。断电、进程退出或结果保存失败后，`submitting` / `unknown` 任务仍要求先核对实际出纸，再通过原有“核对后重试”入口确认。已完成和结果未知的回执均不会按条数裁剪。账本或首次迁移所需的旧文件无法读取时停止打印，避免丢失去重证据。

迁移电脑或备份同步目录时，应在退出同步助手后同时保留 Excel、配置、旧 JSON 和新 SQLite 账本。不同电脑各自维护账本，不承诺跨电脑共享去重。升级后不要直接用旧版助手操作同一数据目录，旧版不会读取新账本。不要把这些文件当作构建缓存清理。

## 文件命名规则

同步助手支持两种命名方式：

- `file_name`：手机端传入精确文件名时，电脑端按该名称保存。
- `name_suffix`：手机端只传入后缀时，电脑端按业务类型拼接文件名。

例如：

```text
入库单_无锡总仓_20260518_02.xlsx
出库单_无锡总仓_20260518_01.xlsx
盘点单_无锡总仓_完整数据_20260518_01.xlsx
盘点拆包标签_20260518.xlsx
订单标签_20260518.xlsx
```

如果手机端传入 `file_name`，以手机端文件名为准；这是当前 APP 重新同步历史单据时使用的主要方式。

## Excel 处理说明

- 同步助手接收的是手机端生成的 `.xlsx` 文件。
- 入库、盘点等多 Sheet 文件会保留原 Sheet 结构。
- 同步助手会补充基础字体、边框、居中和列宽。
- 为避免历史数据很大时卡顿，样式处理只采样前面部分行。

## 常见问题

### 手机连接失败

1. 确认电脑和手机在同一局域网。
2. 确认同步助手正在运行，托盘图标没有退出。
3. 在电脑浏览器打开 `http://localhost:8080/health`，确认服务正常。
4. 检查 Windows 防火墙是否放行 8080 端口。

### 同步失败但服务在线

1. 检查 `D:\数据同步` 是否有写入权限。
2. 确认目标 Excel 文件没有被 WPS/Excel 正在占用。
3. 查看同步助手同目录下的 `日志记录.log`。

### 先积拆包标签
