# 统一数据库紧凑快照与备份校验

## 用户授权与范围

用户确认统一升级、手动、前台及后台定时备份的生成方式，并要求以数据安全为首要约束。本轮只改备份文件生成和校验，不迁移业务表、不删除业务记录、不改变触发时机、NAS 地址、远端编号或恢复入口。工作区已有多轮未提交修改，本记录只说明这一轮备份变更。

所有备份仍为完整 SQLite 数据库。数据和结构完整是正确性标准，文件大小或哈希不作为唯一标准；Expo 内置 SQLite 与 Android 系统 SQLite 仍可存在内部布局差异。

## 实现与保护

- `client/utils/sqliteSnapshot.ts` 新增前台快照生成器。源连接在既有串行保护内、SQL 写事务之外执行 `VACUUM INTO`，只写独立临时目录中的新文件，不对运行中的原库执行原地 VACUUM。
- 校验新快照非空，使用独立 Expo 连接并启用 query_only，执行完整 `PRAGMA integrity_check`，要求唯一 `ok`；对照源连接的完整表、显式索引、触发器和视图 SQL 定义，不依赖物理 rootpage。
- 校验连接成功关闭后，重新检查最终目标不存在，再移动到正式备份名。目标已存在时拒绝，失败不降级为未经校验的裸复制，也不返回成功路径。
- 临时子目录使用 `intermediates:false` 独占创建，只有创建成功后才取得清理权；异常清理仅限本次目录，不删除源库、已有目标或备份父目录。
- 本地 file URI 使用专门的路径解析，不依赖 React Native 仅支持 HTTP pathname 的 URL shim。拒绝非本地协议、远程主机、查询/片段、NUL、UNC、反斜线等不受支持路径；规范化点段以拦截原库路径别名，解码一次后单独转义 SQL 字符串。
- `client/utils/database.ts` 的 `exportDatabaseFile()` 接入生成器，保留原有串行队列、WAL checkpoint、错误重试、独立备份命名和返回接口。`createRealtimeDatabaseBackupFile()` 的连接与扫码队列检查不变，升级前备份失败继续阻止安装。
- 后台 Worker 模板与现有 Android 文件同步新增快照校验：同一源连接读结构，按既有逻辑 VACUUM INTO，随后只读打开快照，完整性和结构均通过才返回供上传。失败沿原有清理和有限重试处理，不上传或标记成功。
- 后台调度、防重入、源库/WAL 签名、上传目标和恢复保护未改动。没有用实时源库的后续行数去判断旧快照完整性，避免并发新业务写入造成误判。

## 回归与交付边界

- 前台快照与实际出口专项共 37 项：真实 WAL、BLOB/NULL/中文、单引号与编码路径、AUTOINCREMENT 高水位、schema/内容完整、已有目标/原库别名保护、失败清理、不擅自提交或回滚、默认 Expo 适配器、checkpoint/队列/并发出口顺序。
- 原生备份专项共 27 项：模板一致、调度与业务数据判定不退化、真实 WAL 完整快照、完整对象清单、只读验证字节不变、缺失对象、坏文件头和实际破坏叶子索引时拒绝。
- 新增 Kotlin 校验代码使用 Kotlin 2.2 与 Android 36 SDK 独立编译通过，没有运行 Gradle 或打包 APK。
- 客户端最终完整 Jest：120 套、1698 项全部通过，最终进程退出码 0，并另存退出码记录。中途为补充移动端本地路径兼容而主动停止的旧测试进程未计作通过。
- 客户端最终全量 TypeScript、ESLint 通过，退出码均为 0；`git diff --check` 通过。
- 使用最终生产 helper 再次验证两个实际数据库的独立副本，18 表、3493 行逐字段一致且原文件哈希不变；额外核对重建后的隐式 ROWID，本次两个数据集均未发生变化。

桌面 SQLite 与模拟 Expo I/O 不能替代 PDA 真机验收。前台改变可由 JavaScript 代码分发，但后台 Worker 的新增校验属于原生改动，完整效果需重新构建并安装 APK。本轮不构建 APK/EXE，不发布热更新，不上传/替换 NAS 文件，不提交或推送 Git。
