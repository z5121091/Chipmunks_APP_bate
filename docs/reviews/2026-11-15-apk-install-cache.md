# APK 安装包复用与取消安装后的继续安装

日期：2026-11-15。范围仅为设置 → 应用更新的完整 APK 下载及安装入口；不改变热更新机制。

## 行为

1. APK 完整下载并校验后，在应用私有 `apk-update-cache/` 中保存安装包和独立的 `completed.json` 登记。记录包名、版本、安装编号、远端文件标识、本地长度和 MD5，不写入业务数据库，也不存下载地址或发布凭证。
2. 系统安装器被取消、APP 切到后台或重新启动后，再次检查到同一个更新，重新核对远端文件标识和本地完整性。有效缓存使用原有操作按钮显示“继续安装”，不新增按钮或放大弹窗。
3. 每次进入安装器前，仍执行现有安装前 NAS 数据库备份。上次备份不能替代这次备份；备份失败阻止安装，但保留完整 APK，允许再次备份并继续安装。
4. 目标版本或文件身份变化、文件消失、长度或 MD5 不符时不复用。远端没有可用文件标识或探测失败时，不冒用旧身份宣布可复用；按正常下载流程处理。
5. 安装器返回包含用户取消，不视为安装成功。只有后续检查读到 APK 内置的原生安装编号达到目标，才精确回收登记过的对应文件。不根据可被热更新替换的 JS 版本号推断安装完成。

| 文件 | 本轮职责 |

| `client/utils/apkUpdateCache.ts` | 私有缓存登记、串行化操作、本地完整性验证、待回收引用、安全清理 |
| `client/utils/apkUpdateArtifact.ts` | 有限超时的 HEAD 文件身份核对、真实下载响应头身份解析、读取 APK 内置安装编号 |
| `client/utils/apkUpdateDownload.ts` | 保留现有主备线路及隔离下载任务；补传真实成功线路响应头、检查未压缩响应长度 |

## 完整性与清理保护

- 身份优先采用强 ETag 与长度，缺少强 ETag 时可采用规范 Last-Modified 与长度；它们是服务器文件变更标识。本地 MD5 只用于发现缓存被修改，不代表发布方数字签名认证。
- 下载可能从主线路回落中转，因此缓存身份取实际成功下载响应，不把之前主线路 HEAD 的身份直接赋给中转下载的文件。
- 目标变化和校验失败先退休引用，保留安装器可能仍在读取的文件；真实原生版本确认后再回收。
- 路径只允许专用目录中的 `installer-数字-数字-数字.apk`。不扫描或删除数据库、备份、其他缓存目录。
- 元数据采用同目录临时 JSON 后重命名替换。落盘失败时完整 APK 仍可本次安装，但不承诺下次启动能恢复缓存；未能登记的孤立文件交给系统缓存回收。
- 如果文件校验本身失败，阻止进入备份和安装；不将其当成单纯的元数据保存失败。
- 旧版本曾下载但未建立登记的安装包不做猜测认领；功能生效后的首次下载会建立登记。系统主动清除应用缓存后也会按正常流程重新下载。

## 验证范围与限制

最终整体验证：客户端 TypeScript 全量通过，ESLint 全量通过，完整 Jest **122 个套件、1795 条测试全部通过**，三个检查进程退出码均为 0；Git diff 空白检查通过。测试使用隔离文件系统及数据库接口，不写真实作业数据。

UI 只调整原有按钮与状态文案，沿用原有卡片尺寸、操作区和单个正文滚动容器，没有新增滚动嵌套或展开动画。组件测试能验证文字和层级，不能代替 PDA 的真实系统安装器、后台恢复与大小屏排版验收。

建议 PDA 验收：完整下载后取消系统安装器 → 再点“继续安装”；取消后继续作业再安装 → 确认重新做 NAS 备份；完整下载后退出 APP 并重新检查更新 → 显示“继续安装”；系统清除缓存后再试 → 正常重新下载。
