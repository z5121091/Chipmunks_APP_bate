# 构建工具与同步助手窗口图标统一

本轮范围：Windows 自有窗口标题栏图标。沿用 `scripts/icon.ico`，不调整窗口尺寸、按钮布局、数据库、同步协议或打印内容。

## 核查与修改

- 构建工具的改动分析、任务记录、存储管理及其清理确认、退出任务窗口没有设置应用图标。主窗口、设置窗口和签名密码窗口之前各自提取 EXE 图标，失败会回退系统默认图标。
- 新增 `scripts/apk-builder/BrandedForm.cs`，所有六类自有 Form 继承统一窗口基类。每个窗口持有独立图标副本并在关闭时释放，关闭子窗口不影响主窗口和托盘图标。
- 正式构建与隔离测试编译都将同一个 ICO 嵌入托管资源。正式 EXE 文件图标仍使用此 ICO；窗口图标不依赖工作目录或松散外部图标文件。
- 同步助手的配对设置和连接二维码已有默认应用图标，未将这两处夸大为已复现缺陷。本轮将配对、二维码和日志三个窗口统一到 `scripts/sync_window_icon.py`，显式设置当前窗口及后续窗口的默认图标，并补齐日志窗口未显式传路径时的应用图标回落。
- 源码目录和 PyInstaller 单文件提取目录均沿用现有 ICO；同步助手已有托盘自定义图标保持原样，系统文件选择器及提示内容中的警告/错误语义图标不在替换范围。
- 同步助手构建缺少 ICO 时明确失败并保留上一份 EXE，避免继续生成系统默认图标的成品；改动分析清单补入新共用图标模块。

## 验证

- 构建工具窗口回归：26 项通过，其中逐类核对真实窗口句柄 `WM_GETICON` 的 16/32 像素图标与应用资源一致，并覆盖维护窗口、清理确认、退出任务、设置及三种签名输入窗口。原有最小窗口和 150% 缩放布局回归通过。
- 构建工具支持逻辑：17 项通过，包含新同步助手图标模块的改动识别。
- 同步助手构建协议：19 项通过；包装器使用隔离的假打包程序，不生成真实同步助手 EXE。缺少图标的用例在打包前失败，旧文件保留。
- 同步助手图标、配对、二维码、日志：43 项通过；覆盖真实隐藏 Tk 窗口、源码/单文件资源路径与图标读取。

测试只编译隔离的 C# 测试程序，没有覆盖正式构建工具或同步助手 EXE，没有启动同步服务或读写真实业务配置。重新打包后的正式 EXE 与 PyInstaller 单文件运行仍需用户构建后验收。
