# 未绑定供应商物料的查看与补充分配

日期：2026-11-14。项目：`D:\Chipmunks_APP`。

## 用户可见行为

设置 → 物料绑定 → 维护供应商，新增紧凑的“未绑定供应商的物料”入口并显示数量。进入后分页展示型号、存货编码和完整版本列表，可按型号、编码、任一版本搜索。点击某条物料，在当前窗口内选择现有供应商，点击“保存分配”后才真正保存；也可以直接返回，保留未绑定。

保存成功后返回未绑定列表、重新读取当前页及总数，并刷新供应商使用数量和主物料绑定列表。当前页因记录减少而越界时，由分页 API 自动回到有效页。

## 弹窗与编辑草稿

- 使用现有 SupplierManager 所属的原生 Modal，维护、未绑定列表、分配选择三个界面在内部切换，不再叠加原生弹窗。
- 关闭按钮、底部返回和 Android 返回遵守：分配供应商 → 未绑定物料 → 维护供应商 → 原供应商选择／关闭。保存中禁止返回和重复提交。
- 搜索切换不自动打开键盘；切换层级时主动收键盘。长物料信息和错误放在列表可滚动头部，不占满固定区域而挤没可选项。
- 如果从某条物料的编辑表单进入，再给同一条物料分配供应商，精准同步该表单中的供应商，避免随后保存把新值恢复为空。给其他物料分配时，原编辑草稿不变。
- 隐藏、卸载、快速搜索和离开再进入均校验活跃状态／请求序号，迟到响应不能覆盖当前页面或修改旧表单。

## 数据边界

- “未绑定”包含 NULL、空字符串及普通／全角等纯空白字符；没有自动给用户有意留空的记录分配供应商。
- 原生 SQLite 在数据库内过滤、统计和分页，搜索的多字段 OR 整体与“未绑定”条件 AND；Web 预览保持相同过滤和多版本搜索语义。
- 新增 `assignInventoryBindingSupplier(bindingId, supplierId)`，在独占事务内确认物料仍存在、仍未绑定、供应商仍存在，只写 supplier 一列。已被其他操作分配的记录拒绝覆盖，写失败回滚。
- 不修改型号、存货编码、版本别名、备注、创建时间或历史业务记录；不需要数据库迁移、原生依赖或 ERP 接口变更。
- 保存遇到物料已变更的错误后，返回物料列表会重新查询，避免旧行反复导致同一错误。

## 后续实机反馈：两个列表不能向后滑动

用户反馈 7 条未绑定物料仅显示约 4 条，分配页十几个供应商也只能看到前面几条。源码核查发现两页内部列表被 AppModalCard 的同方向整卡 ScrollView 包裹；外层内容没有有限高度，且正常状态外层禁止滚动，导致内部列表没有得到正确视口，超出部分又被卡片裁切。此前业务测试 mock 了卡片和列表包装，没有覆盖这条真实层级，不能据其通过认定物理滑动已正常。

修复范围：

- AppModalCard 新增可选 `scrollMode="body"`：用 flex:1 / minHeight:0 的普通 View 贯通固定卡片的高度，不再在列表外包同向 ScrollView；原有默认表单模式保持原行为。
- 未绑定物料和分配供应商两页采用该模式并使用原生 FlatList，明确启用滚动、滚动条及拖动收键盘；已有 AppModalViewport 负责键盘高度避让，不再叠加键盘列表包装。
- 维护／选择供应商窗口同步使用同一种有界列表容器。切换物料列表与供应商列表使用独立 key，翻页或更换查询时回到该页开头，避免继承上一列表的滚动位置。
- 不修改数量统计、供应商分配事务、保存、搜索或返回层级。
- 增加真实 AppModalCard +真实 styles +原生 FlatList 回归，覆盖 7 条物料、18 个供应商，320/360/768 dp、字体1.0/1.3；检查列表祖先、有限高度链和末项选择保存。该验证不冒充真实 PDA 拖动验收。
