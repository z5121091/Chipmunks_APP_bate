# UI 修改与验收清单

适用项目：`D:\Chipmunks_APP`。建立日期：2026-11-13。修改 UI 前阅读；审查起点和本轮改动应能从 Git diff 中核对。

## 1. 先确认现有组件与实际层级

- 先读取目标页面、styles、复用组件和最近相关测试，再改代码。新增动作需用户提出或是完成已授权功能所必需，不能为了排版自行加按钮。
- 复用现有主题、圆角、间距和控件，不单独发明一套弹窗或按钮。普通展开不恢复动画；当前项目已取消易冲突的展开高度动画。
- `AnimatedButton` 的 `containerStyle` 作用在外层 `Animated.View`；`style` 作用在内层触摸区，内层默认宽度 100%。同行布局的 flex、宽度和 minWidth 要约束在外层；不要只改内层。
- 按使用目的区分：主操作可铺满可用空间；同行工具按钮按父容器分配；“移除”等短动作按文字收紧。不要把每个按钮都套全宽或 flex: 1。

## 2. 响应式规则

- 样式工厂用 `useResponsiveStyles(theme, createStyles)` 订阅窗口和系统字体变化；不能只按 theme 缓存包含尺寸的样式。调用方已有显式完整尺寸依赖的 memo 可以保留。
- `Spacing`、`BorderRadius`、`BorderWidth`、`Typography`、`UI_REDESIGN_TOKENS` 在创建样式或渲染时读取；不要在模块顶层解构并保存响应式数值。额外缓存须覆盖其真正依赖的窗口、像素密度、主题和安全区参数。
- 将模块级 StyleSheet 改为工厂时，全文件查找 styles 的消费者，包含文件末尾独立子组件；每个消费者都要获得对应的响应式 styles，不能只处理默认导出页面。
- 控件间距、圆角和图标用有上限的 `scaleControlSize` 或主题 tokens；`rs/wp/hp` 保留给确实需要按画布缩放的几何尺寸。固定宽度弹窗不能跟着大屏无限放大 padding。
- 键盘开关不能让全局字号、间距或卡片尺寸忽然缩小。宽度缩放和真实窗口高度限制分别处理；不再为键盘单独缩窗。
- 长文案先算空间：父容器减去外边距、padding、gap、图标才是文字槽。优先让长动作独占一行或调整布局，不把无限缩字当作适配。

## 3. 弹窗与输入焦点

- 按 2026-11-14 最新约定，不再加入键盘自动避让、聚焦后自动滚动或随输入法压缩/抬升窗口；Android 主窗口与 Modal 使用 `adjustNothing`。保留扫码自动聚焦、主动收起键盘和手动滚动，这些不属于自动避让。
- 编辑弹窗使用普通 View 实现的 `AppModalViewport` 测量真实窗口 padding 内的可用高度；`AppModalCard` 的预设最小高度不能超过它。横竖屏、分屏和短窗口仍需适配，不能冻结窗口高度来伪装取消键盘压缩。
- 正常窗口保留固定操作区和可滚动正文；极短窗口下要提供能到达操作区的滚动退路。必须核对头、正文和页脚的合计尺寸，只有 maxHeight 并不能证明按钮可达。
- 纵向 FlatList 不得放进同方向、没有有限视口高度的 ScrollView。固定高度的列表型 AppModalCard 使用 `scrollMode="body"`，由内部列表独立滚动，标题和操作区留在列表外；表单的整卡滚动退路不能直接套到列表上。滚动回归应保留真实卡片和列表层级，不能全部 mock 掉后只检查数据或点击回调。
- 表单正文已有自己的纵向滚动时，也应明确使用 body 模式并保留普通手动滚动；不要再让 Screen 或整卡重复包裹。list 预设必须提供有限高度，短内容可以按实测内容收紧，不能只给外层 maxHeight 就认为内部视口已确定。
- 修改后运行 `client/utils/__tests__/scrollOwnershipArchitecture.test.ts`，自动检查上述两种包装关系；同时保留真实组件层级回归和目标设备的首项到末项拖动检查。源码护栏不能替代布局和触摸验收。
- 修改 Android 输入法/窗口策略时，运行 `node --test client/scripts/check-android-keyboard.cjs` 检查真实插件生成、重复执行与主窗口/Modal 策略；原生改动需新 APK 验收，不能只靠热更新。
- 高度变化时保持子树结构和输入实例稳定，避免焦点重建、键盘反复开关。关闭弹窗后才恢复底层扫码焦点；检查首次打开、返回、提交中关闭及迟到响应。
- 不修改业务校验、仓库/账套归属或扫码队列来补 UI。共用组件修改后，至少回归物料绑定、供应商选择、拆包、内部建标和标签补打。

## 4. 必须核对的尺寸与状态

- 宽度 320、360、600、768、1024 dp；系统字体 1.0、1.3；长供应商名、长规格、最长动作文案。
- 小屏冷启动、大屏冷启动、窄→宽→窄；相同最终尺寸不应因首次打开尺寸不同而不同。
- 键盘弹出/收起、窗口很矮、正文超长、空列表、加载/失败/禁用状态；键盘不抬升窗口，保留用户收起键盘、手动滚动到关键操作的正常路径。
- 回归展开、返回、切账套和扫码弹窗焦点，避免把已有行为改坏。
