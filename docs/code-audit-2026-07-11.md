# 掌上仓库全维度代码审核（2026-07-11）

## 审核范围

- 前端：扫码出库、采购入库、扫码入库、库存查询、设置、首页与反馈工具。
- 后端：扣子中转、畅捷通业务路由、消息回调、授权管理、状态持久化与上传接口。
- 业务：两账套分流、订单语音、ERP 明细匹配、拆包、缓存与主动刷新。
- UI：小屏/大屏首页布局、按钮层级、状态信息与焦点恢复。

## 已修复

### 前端与业务逻辑

1. 移除客户端源码中的 NAS 密码：默认更新地址不再携带用户名密码，`version.json` 使用相对下载路径，构建时可通过 `UPDATE_SERVER_URL` 注入实际地址。
2. “切换订单”必须满足当前订单已有扫码物料；空订单切到新单播报“新订单”。
3. 未绑定存货编码播报“未绑定”，ERP 明细不存在播报“不在本单”，已超数量播报“超量了”。
4. 语音队列等待上一条播报完成，避免连续扫码时后一句停止前一句。
5. 拆包确认、取消、仓库切换以及“拆包已保存但后续失败”均恢复扫码焦点。
6. 入库保存失败后同步释放焦点锁并回到扫码输入框。
7. 手动刷新与下拉刷新使用缓存旁路，确保真正访问 ERP；普通进入页面仍使用缓存。
8. 现存量前端和中转缓存分别为 15 秒，最坏陈旧时间约 30 秒。
9. 采购入库列表和详情缓存路径改为前端实际调用的畅捷通路径。

### 两账套与迁移

1. 所有 ERP 请求携带 `X-Erp-Account-Key`。
2. 账套标识固定为 `wuxi-duneng` 与 `shanghai-chipmunk`。
3. 扣子中转按账套选择独立目标服务器，缓存键也包含账套，避免相同单号串账。
4. 每台 ERP 应用服务器通过 `CHANJET_LOCAL_ACCOUNT_KEY` 声明所属账套。
5. 请求账套与服务器账套不一致时返回 HTTP 409，不调用畅捷通。
6. 健康检查返回服务器账套，设置页会核对并拒绝错误连接。
7. 上海账套默认关闭；配置服务器后通过前端环境变量显式启用。
8. 正式迁移只需要修改环境变量或 `server/erp-proxy.config.json`，业务接口路径不变。

### 后端

1. 销售出库单、采购入库列表、采购入库详情与现存量使用分接口短缓存。
2. 缓存使用账套、方法、路径和请求体生成键，并采用最近使用顺序淘汰。
3. 响应提供 `X-Cache`、`X-Erp-Account-Key` 与 `Server-Timing`，便于判断耗时来自缓存还是 ERP。
4. 两个畅捷通消息回调兼容地址都纳入同一限流器。
5. 管理接口继续要求独立管理密钥。
6. 消息回调继续拒绝明文伪造消息，只接收畅捷通加密消息。
7. 畅捷通状态继续使用原子写入和备份文件。

### UI

1. 首页把出库和入库设为第一层大按钮。
2. 盘点、物料绑定、单据管理和库存查询改为 2×2 次级按钮。
3. 备份状态移到快捷作业下方，并可直接进入设置。
4. 卡片尺寸按小屏、普通屏和大屏分别约束，保持稳定点击区域。
5. 首页继续只显示首页自己的底部导航，其他业务页面不增加底部栏。

## 延迟结论

- 第一次查询仍需经过 APK/扣子、ERP 中转服务器和畅捷通，约 1 秒属于冷请求链路耗时。
- 相同查询在缓存有效期内会明显变快，并减少畅捷通接口次数。
- 主动刷新明确绕过缓存，因此会恢复到真实 ERP 请求耗时。
- `Server-Timing` 可用于区分中转耗时与畅捷通上游耗时。

## 保留项与风险

1. 按既定决定，未实现采购入库单超过 100 条的分页；当前未审核单据量较少。
2. 上海花栗鼠服务器、应用凭据和 Token 尚未配置，因此保持“未开放”。
3. ERP 业务接口密钥此前因扣子兼容问题已回滚，目前依靠限流与缓存控制访问；管理接口不受此回滚影响。
4. 原生自动备份若访问需要认证的 WebDAV，云构建环境必须配置 `UPDATE_SERVER_URL`；正式环境更稳妥的方案是让服务端代管 WebDAV 凭据。
5. 内存缓存会在服务重启后清空，这是预期行为，不会影响数据正确性。
6. 本轮按要求未运行 Expo、Metro、APK 构建或 TypeScript 编译，仅进行静态代码审核。
