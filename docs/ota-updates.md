# APP 热更新第一版

## 使用顺序

1. 使用根目录的 `掌上仓库构建工具.exe` 构建一次 APK，并覆盖安装到 PDA。不要卸载清空数据。此前的 APK 未启用热更新，不能靠热更新启用自身。
2. APP 设置里的“应用更新”独立于“关于掌上仓库”，包含 APK 版本与热更新两个区域。原 NAS APK 下载、校验和安装流程继续复用。
3. 后续完成前端修复后，构建工具选择 APK，可选填写主窗口底部的更新说明，然后点击“生成并发布热更新”。任务直接使用主窗口日志区，不打开发布弹窗。自动检查兼容性、导出 Android Hermes 代码及依赖资源、计算校验值、通过 HTTPS 发布。
   本地产物保存在 `dist/ota/年-月-日_时-分/`，例如 `dist/ota/2026-11-02_21-56/update.zip`；同一分钟重复生成时依次加 `_02`、`_03`，不覆盖已有文件。目录和更新包的完整路径会显示在任务日志中。
4. PDA 启动成功后自动检查并下载，也可手动检查。不会自动重载正在使用的 APP。下载完成后只在工作台弹窗提醒，可直接点击“立即应用”，无需跳转更新页面，也可选择“稍后”；同一更新只自动提醒一次，不在扫码页弹出。应用更新页显示“已下载，待应用”，保留手动应用入口。
5. 点击“立即应用”，检查保存/同步/打印提交状态，并完成数据库 checkpoint 后重新加载。运行新版且数据库初始化完成后，记录真实生效编号和时间，并在工作台用 APP 统一的成功药丸提示一次“热更新已完成”；显示在底部导航上方，不带按钮、不遮挡操作，约 1.5 秒后自动消失。

## 发布限制

- 第一次成功构建 APK 后，工具在 `dist/apk/ota-baseline.json` 保存原生兼容性基准；只有基准相同且 APK 版本未改变，才允许发布。
- 原生 Android 文件、插件、原生动画参数、依赖清单、补丁、锁文件、应用配置变化会保守地要求重建 APK。普通 TS/TSX 业务文件不影响原生指纹。
- 没有成功构建基准时会拦截发布。不要手工编辑基准或运行版本来绕过检查。
- 发布当前源码的完整前端版本；发布前应完成所需修改和测试。不会自动区分试验代码。
- 热更新发布不会上传源码、ERP 密钥、SSH 登录信息或 APK 签名文件。前端公开配置与 APK 的公开配置保持一致。
- 当前电脑的发布令牌保存在 `%LOCALAPPDATA%\ChipmunksBuildTools\ota\publish-token.bin`，使用 Windows DPAPI 当前用户加密。换电脑时使用“设置 → APK 发布签名 → 导出构建配置备份 / 恢复构建配置备份”。一个 `.cwbuild` 同时迁移签名和发布凭据，使用自己设置的备份密码。旧 `.cwsign` 仍兼容，但不含发布连接时保留本机现有连接。
- 上传 ZIP 的体积不等于 PDA 实际下载量；服务器提供按资源哈希寻址的文件，PDA 可以复用已有资源。
- 图片/字体沿用 Metro 缓存标识以复用 APK 内置资源；服务器存储与完整性校验单独使用 SHA256。多倍图未匹配时正常下载，不强制复用错误尺寸。
- 支持 gzip 协商传输，压缩副本同原始资源一起参与引用保护和过期清理。下载限速按压缩后的实际传输字节计算。
- 服务器收到当前运行编号与最新编号相同的检查请求时返回无更新。APP 也核对运行编号、待应用编号及时间，防止把已生效或更旧的缓存更新再次提示为待应用。

## 服务器隔离

- 独立进程：`warehouse-ota.service`，只监听 `127.0.0.1:18321`。
- 程序：`/opt/warehouse-ota`；数据：`/var/lib/warehouse-ota`；发布令牌：`/etc/warehouse-ota.env`。
- HTTPS 路径：`https://erp.chipmunks.fun/app-updates/`。Nginx 仅增加专用 location，并平滑 reload。
- 原 ERP 双账套、网关、小程序进程不重启，不修改账套环境文件及滚动 Token。
- 下载连接共用约 160000 字节/秒预算，不按单个连接分别计算。
- 上传先认证并验证资源校验值，所有资源写入后原子替换该运行版本的清单。失败不会替换此前可用清单。
- 每个运行版本当前可用的更新永久保留，不因旧 PDA 长期离线而删除；不自动删除整个运行版本。
- 同一运行版本最近 5 次发布保留；超过这 5 次且已超过 30 天的历史发布才清理。
- 资源文件只有在不被任何保留清单引用、且落盘已超过 7 天时才删除，共用的图片/字体不会随某次历史发布一起误删。
- 每天北京时间 03:40 由 `warehouse-ota-cleanup.timer` 清理，任务结果写入 systemd 日志。发布和清理共用进程间锁，避免正在上传时被清理。
- 旧 APK 恢复联网后直接获取对应运行版本的最新完整更新，无需逐次补齐中间版本；仍需重建 APK 的原生变化不会跨运行版本推送。
- 第一版未提供用户端回退按钮。

## 检查方式

- 设置 → 应用更新：确认 APK 版本、当前运行的热更新编号、更新内容；检查 APK 仍走原 NAS 流程。
- 发布一条前端文字修复，PDA 下载后确认仍运行旧编号。点击“立即应用”，确认重新加载、回到工作台，编号变为新编号且提示只出现一次。
- 关闭网络：应继续使用原版，手动检查时说明失败；恢复网络后可再次检查。
- 保存、同步或打印提交尚未完成时，应用应被拦截；完成后可再应用。
- 修改原生文件后尝试发布：应要求构建 APK，不应上传不兼容更新。
- 首次安装及真实 PDA 重载仍需设备验收。WEB 预览不支持原生热更新。
- 电脑构建工具 → 设置 → 热更新发布连接 → 测试发布连接：检查本机凭据及服务器发布权限。连接地址固定使用受 HTTPS 证书保护的域名，工具界面不直接显示公网 IP。EXE 不内置 SSH 账号密码，也不内置可直接提取的发布凭据。
