# 掌上仓库 UI 重设计蓝图

## 1. 产品 Slogan

**扫码即落库，仓库更稳。**

辅助表达：

- 高频扫码，少一步就是快一步。
- 数据看得清，操作不打断。
- 从入库、出库到盘点，每一笔都有迹可循。

## 2. 设计语言

掌上仓库不是展示型应用，而是高频作业工具。界面应服务于扫码、核对、修改、同步这些连续动作。

核心设计语言：

- **稳**：关键数据、当前状态、错误提示必须清楚；危险操作必须有明确边界。
- **快**：高频入口放在第一屏；操作按钮尺寸稳定，不因为文字变化跳动。
- **清**：列表项之间必须有可辨识分隔；型号、数量、仓库、状态必须形成固定阅读顺序。
- **轻**：减少厚重装饰，保留必要的卡片边界、状态色和图标。
- **一致**：入库、出库、盘点、单据、设置使用同一套标题、工具条、列表项、弹窗和空状态规则。

## 3. 体验流程图

### 高频作业主线

```text
首页
  -> 扫码入库 / 扫码出库 / 盘点作业
    -> 选择或识别仓库
    -> 扫码输入
    -> 即时写库
    -> 当前批次列表确认
    -> 导出 / 同步 / 返回首页
```

### 出库订单主线

```text
首页
  -> 出库订单
    -> 查看订单列表
    -> 展开物料
    -> 编辑数量 / 拆包
    -> 默认同步到电脑
    -> 自动回到扫码出库
```

### 配置维护主线

```text
首页
  -> 设置 / 物料绑定 / 规则配置 / 仓库档案
    -> 搜索或筛选
    -> 新增 / 编辑 / 删除 / 导入导出
    -> 成功反馈
    -> 留在当前上下文
```

## 4. 原型图规则

### 首页

首页可以重新布局，但必须保留“工作台”属性。

建议结构：

```text
[掌上仓库]                          [设备/备份状态]
扫码作业
┌──────────────┐ ┌──────────────┐
│ 入库扫码      │ │ 出库扫码      │
│ 今日数量/入口 │ │ 当前订单/入口 │
└──────────────┘ └──────────────┘

常用处理
┌──────┐ ┌──────┐ ┌──────┐
│订单  │ │盘点  │ │物料  │
└──────┘ └──────┘ └──────┘

系统维护
┌──────┐ ┌──────┐ ┌──────┐
│设置  │ │规则  │ │仓库  │
└──────┘ └──────┘ └──────┘
```

### 扫码页

```text
[返回] 页面标题                 [仓库]
[步骤/状态条：订单 -> 客户 -> 物料]
[扫码输入框，高对比边框]
[当前订单/客户/仓库状态条]
[本次已扫列表]
  型号             数量
  版本 / 批次 / 追溯码
  [展开明细]
```

### 列表配置页

以物料绑定为标准样式：

```text
[返回] 物料绑定
[搜索摘要 + 总数]
[搜索] [新增] [模板] [导出] [导入]
[搜索面板，可展开]

┌────────────────────────────┐
│ 型号 EM74HC595AD             │
│ 存货编码 Y090007             │
│ 供应商 xxx                   │
│                    [编辑][删]│
└────────────────────────────┘
间距
┌────────────────────────────┐
│ 下一条记录                   │
└────────────────────────────┘
```

要求：列表项之间必须有 `gap`、边框或背景差异，不能只靠文字自然断开。

## 5. 组件规范

### 页面骨架

统一使用：

- `Screen`
- `PageHeader`
- `PageToolbar`
- `PageSection`
- `AppEmptyState`
- `AppModalCard`
- `AppModalActions`

建议新增或统一封装：

- `PageHeader`：返回、标题、副标题、右侧状态。
- `ActionToolbar`：搜索、新增、导出、导入等横向操作。
- `InfoCard`：设置页、仓库页、配置页通用卡片。
- `RecordListItem`：普通业务记录卡片。
- `AggregatedRecordItem`：入库、出库、盘点聚合记录。
- `DocumentCard`：入库单、出库单、盘点单列表。
- `StatusPill`：待同步、已同步、失败、当前仓库、当前筛选。
- `DangerAction`：删除、清空、恢复等危险动作。

### 列表项规则

所有列表项必须满足：

- 有明确外边距或 `gap`。
- 有背景色和边框，不允许纯文字堆叠。
- 主标题一眼识别：型号、订单号、仓库名、规则名。
- 次级信息固定顺序：仓库/编码/版本/批次/数量/时间。
- 右侧操作按钮固定尺寸，优先图标按钮。
- 展开态必须有内层背景或边框，不能和父级混在一起。

### 工具条规则

- 高频主操作使用主色按钮。
- 次操作使用浅底按钮。
- 按钮高度统一 44。
- 横向工具条可滚动，但每个按钮宽度必须固定。
- 文本必须 `numberOfLines={1}`，长文案用缩写或 tooltip/弹窗解释。

### 弹窗规则

- 表单弹窗统一 `AppModalCard size="form"`。
- 危险操作统一确认弹窗，不在普通 toast 中完成。
- 导入、同步、备份类动作必须有 loading 状态。

## 6. 设计语言上色

保留当前蓝灰底色框架，但收敛为一套功能色。

### 基础色

- 页面底：`backgroundRoot`
- 卡片底：`backgroundElevated`
- 列表项底：`backgroundDefault`
- 内嵌区域：`backgroundTertiary`
- 主文字：`textPrimary`
- 辅助文字：`textSecondary`
- 弱提示：`textMuted`

### 功能色

- 入库：绿色 `success`
- 出库：蓝色 `accent`
- 订单：琥珀 `warning`
- 盘点：红橙状态色，降低饱和度
- 物料绑定：青色 `cyan`
- 设置：灰蓝

### 状态色

- 成功：绿色，只用于成功/已同步/可继续。
- 警告：琥珀，只用于需要注意但不阻断。
- 错误：红色，只用于失败、删除、风险提示。
- 信息：蓝色，用于当前筛选、当前仓库、当前步骤。

### 不推荐

- 大面积纯渐变。
- 页面级嵌套卡片。
- 同一个页面出现 3 种以上卡片圆角。
- 只有背景色变化、没有边框/间距的列表分隔。

## 7. 当前代码审查发现

### 已有优势

- 已有主题系统：`theme.ts`、`colors.ts`、`Typography`、`Spacing`。
- 已有共用基础组件：`Screen`、`AnimatedButton`、`AppModalCard`、`AppEmptyState`。
- 入库、出库、盘点已部分使用 `AggregatedRecordItem`，有统一潜力。
- 单据列表已有较成熟的 `documentCard` 和展开明细结构。

### 主要问题

- 页面 header/card/toolBar 各自实现，间距和阴影不一致。
- 配置页和业务页的信息层级差别大，用户从一个模块切到另一个模块需要重新适应。
- 部分列表项分隔弱，尤其是物料绑定这类维护页，记录之间不够像“独立对象”。
- 工具条按钮尺寸过去依赖内容和外层容器，容易出现宽度异常。
- 首页入口偏“模块卡片”，但缺少今日状态、备份状态、当前作业提示。
- 设置页功能多，需要分组更明确，避免用户找入口。

## 8. 落地顺序

### P0：设计系统收口

- 新增 `PageHeader`。
- 新增 `ActionToolbar`。
- 新增 `RecordListItem`。
- 新增 `StatusPill`。
- 梳理统一卡片半径、间距、按钮高度。

### P1：高频页面

- 首页重新布局。
- 扫码出库页状态条重做。
- 扫码入库页对齐出库页。
- 盘点页对齐扫码页。

### P2：单据页面

- 出库订单列表。
- 入库记录列表。
- 盘点记录列表。
- 订单拆包/编辑弹窗。

### P3：配置页面

- 物料绑定。
- 仓库档案。
- 规则配置。
- 前缀配置。
- 自定义字段。

### P4：系统页面

- 设置页分组重排。
- 帮助页。
- 更新日志页。
- 404 页。

## 9. 第一轮实际改造建议

第一轮不要全量大改，先选最能统一手感的页面：

1. 首页：重新布局，建立新视觉基调。
2. 物料绑定：作为配置维护页模板。
3. 扫码出库：作为扫码作业页模板。
4. 出库订单：作为单据管理页模板。

这 4 个模板稳定后，再复制到入库、盘点、仓库、规则等页面。
