# 掌上仓库 V1.0 软件著作权登记准备评估

初评日期：2026-09-22；材料复核更新：2026-09-23。范围为当前 APP、配套后端和现有申请材料，不代表登记机构审查结论。本轮未代为提交申请。

## 初步结论

项目已有可运行的规则解析、物料绑定、双账套 ERP、扫码出入库、盘点、导出与备份等业务实现，具有准备软件著作权登记的基础。使用 Expo、React Native 或 AI 辅助开发，不能单凭这一点判断能否登记；重点是申请人对申报的软件享有相应权利，第三方内容来源合法，申报材料真实一致。登记不等于专利授权、应用商店审核或网络安全合规认证。

依据：[国家版权局《计算机软件著作权登记办法》第四、七至十一、二十一条](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/P020241015604759788122.pdf)。

## 提交前需要明确的事项

1. **权利人。** 用户说明软件由本人和上海花栗鼠科技有限公司联合开发，目前希望手册和申请材料仅写公司。手册已按此口径整理，但著作权归属仍应按实际开发关系和双方书面约定确定；仅把公司写在封面上，不能证明公司单独享有全部权利。提交前应确认双方是否约定由公司单独享有软件著作权，并准备相应证明。[《计算机软件保护条例》第十条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/200701/t20070109_50527.html)
2. **名称与版本。** 当前拟申报名称为“掌上仓库 V1.0”，正式版显示名已设为“掌上仓库”，Android 包名为 `com.chipmunks.traceability`，内部 versionCode/buildNumber 为 100。申请表、手册、截图、代码页眉仍需逐项核对；旧版测试截图待正式版打包后更换。应用“关于”页目前仍显示个人账号作为作者，提交前应根据实际权属文件确定是否调整，避免材料署名不一致。内部构建号不是软件登记的显示版本。
3. **日期真实。** 本轮按要求写入“掌上仓库正式发布”作为应用日志，不等于已经公开发行，也不证明实际开发完成日期、首次发表日期。申请日期字段应按真实情况填写，不应依据代码注释或日志自动猜测。
4. **第三方许可。** 已读取 client/server 当前安装的直接运行时依赖 package.json 许可字段：主要为 MIT；js-base64 为 BSD-3-Clause，dotenv 为 BSD-2-Clause，xlsx、drizzle-orm、drizzle-zod 为 Apache-2.0。它们不是明显的登记障碍，但这只是直接依赖元数据核查，不是完整法律审计。仓库内 `client/heroui`、`client/scripts/text-table.mjs` 和 `client/scripts/reporter.mjs` 含第三方来源或版权标记；需要核对具体来源版本及其完整许可文件，不应删除这些标记或把第三方代码列为自行创作。间接依赖、图标字体、供应商 Logo、模板来源及同步助手的 Python 依赖仍需另列清单。
5. **项目自身授权。** 根 LICENSE 曾为 MIT 授权文本，与 README 中的专有软件说明冲突；现已按用户要求删除根 LICENSE 及 README 的许可证段落。若旧版本曾按 MIT 许可对外提供，删除当前文件不会撤销既有授权。第三方组件仍遵循各自许可，个人与公司之间的权属仍需书面文件证明。
6. **AI 辅助部分。** 保留人工需求设计、业务规则、审查、修改、测试和版本记录。不能保证纯自动生成部分的权利判断；如相关部分占比较高，应向登记机构或专业代理说明实际情况、确认材料口径，勿作虚假的“全部人工原创”声明。
7. **更新版本。** 已恢复应用内 NAS 更新入口和安装权限，但 NAS 当前仍发布旧版 3.06 清单，缺少正式版包名字段。应用会提示先换清单，避免把旧 APK 当作新版安装。正式发布前需上传与 APK 一致的版本、包名、安装编号和下载地址，并在 PDA 上验证同签名覆盖安装。

## 材料准备

- 申请表、权利人身份证明、适用的任务书/合作或委托及权属证明。
- 程序鉴别材料与一种文档，例如真实的操作手册。按登记办法，分别提交源程序和文档的前、后各连续 30 页；不足 60 页提交全部。除特定情况外，程序每页不少于 50 行、文档每页不少于 30 行；申请文件使用 A4 纸张。涉及商业秘密时，可按规定申请例外交存或封存。
- 源码按明确、可复核的文件顺序连续编排，优先说明自主业务实现；不把 node_modules、构建缓存或无关第三方代码凑成自有源码。
- 申报材料不包含真实客户、库存、单据、服务器口令、AppSecret、Token、私钥等敏感信息。NAS 更新凭据已从项目源码移到本机私有构建配置；旧凭据曾出现在源码中，仍需更换。代码确需包含商业秘密时，按官方例外交存或封存要求处理。
- 已修改“软著申请材料”中的用户手册，统一为“掌上仓库 V1.0”和公司署名，补充首次配置、同步与备份说明，并保留图3-1首页截图空位供后续补图。申请表信息草稿仍需在确定权属与日期后核对。源码 PDF 曾生成供内部检查；因源码还要修改，已移除该草稿，待最终代码确定后再生成。生成脚本读取列明的自有业务源码，排除已识别的第三方、生成目录与未完成模板，并在输出前扫描常见硬编码密钥形式。定稿时须核对清单是否真实覆盖拟申报程序的前后连续部分，不能仅凭自动脚本判断合规。

材料规则与保密交存依据：[登记办法第九至十三条](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/P020241015604759788122.pdf)。办理时以[中国版权保护中心官方入口](https://www.ccopyright.com.cn/)当前要求为准，避免向相似名称的第三方网站提交凭据。
