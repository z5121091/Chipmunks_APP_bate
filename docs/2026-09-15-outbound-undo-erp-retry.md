## 客户端修复

- 复现了删除出库记录成功、随后的列表刷新失败时，界面仍保留旧数量并暂停扫码的问题。现在数据库删除成功后立即移除对应页面记录；刷新失败不会误报删除失败，下次扫码先重新读取本单记录，读取失败仍禁止写入。
- 遗留的单条/批量拆包记录删除接口原先只删除标签行。现在共用事务删除对应整条出库物料、全部关联拆包标签以及相关批次出库流水，防止出现半对标签和未撤销的数量。
- 当前版本没有独立的拆包记录删除页面，实际使用出库物料明细或单据明细的删除入口；没有新增删除入口。旧 APK 当时的完整现场日志未知，不能把所有旧版卡住都归因于上述问题。
- 原拆包生成的标签已有后续出库时禁止直接删除原拆包。批次流水存在后续入库或盘点校准时，同样保留数据保护，不能强行回退或把库存加两遍。
- 删除失败时展示明确中文原因。单据页面也区分数据库删除失败和删除后的列表刷新失败。
- 不修改无追溯码重复扫描规则、ERP 合并行数量规则和打印机任务队列。已提交到打印机的任务不会因 APP 删除记录自动撤回。

## 后端修复

- 只读 T+ 查询的临时网络错误或 HTTP 500/502/503/504 最多重试一次。连接池失败转 curl 也计入这两次上限；共享原来的超时预算，正常查询无额外请求。
- 不重试 HTTP 400/401/403/404/429，不重试 HTTP 200 中的业务错误。授权、Token 换取/刷新等写操作不进入新增通用重试；原有专用 Token 维护流程保持不变。
- 新增请求标识、上游失败类型、HTTP 状态、标准网络错误码、尝试次数和耗时日志；响应头及错误 JSON 携带请求标识，外层代理透传。
- 不记录请求/响应正文、单号、客户、物料、AppSecret、Token；未知本地异常不再把原始内部异常文本返回前端。
